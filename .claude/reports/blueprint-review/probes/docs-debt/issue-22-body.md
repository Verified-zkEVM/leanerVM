## What is wrong

leanVM's bytecode is public and never committed: the eight bytecode columns ride the seed and finalize blocks as `Coord::Public` (`crates/lean_vm/src/cpu/layout.rs:288-290`, `leaf.rs:36-39`), the verifier evaluates them itself, and specification §6.4 says "The program is public, i.e. not committed". In leanerVM at `main` the program is the `"bytecode"` table of Clean's `ProverData` (`LeanerVM/Arithmetization/Channels.lean`, `programOf`), which is a field of `EnsembleWitness`, so the prover supplies it. Every table `Spec` (`*Spec r next data := *Refines (programOf data) (imageOf data).2 r next`) and `BytecodePull.Guarantees` are stated relative to it. A table's soundness therefore concludes "the row is a step of the program the prover named", and Layer 8's sketch tied that program to the statement's only by the conjunct `programOf w.data = prog`, which leanVM has no counterpart of. No theorem is false; the exported object is weaker than leanVM's.

## The change (decision 13, settled 2026-09-15)

The program is a parameter `prog : Program` of every definition that mentions it, the one place Clean treats a value as public, as leanVM's `layout(prog, …)` takes it. No Clean change is needed. The roadmap already states the target shapes; this issue is the implementation slice.
