# leanSPHINCS security in Lean 4

**`Sphincs.leanSphincsStronglyUnforgeable` proves that leanSPHINCS, the scheme of [`crates/signatures/src/lean_sphincs`](https://github.com/leanEthereum/leanVM/tree/542b0353/crates/signatures/src/lean_sphincs) specified in [`doc/lean_sphincs`](https://github.com/leanEthereum/leanVM/tree/542b0353/doc/lean_sphincs), at leanVM commit `542b0353`, is SUF-CMA secure in the random-permutation model up to `N = 1,182,000,000` signatures, with forgery probability at most `(Q + 1) · 2^-127` for `Q ≥ 1` permutation calls.** ([Security.lean](Sphincs/Security.lean); the statement is `Sphincs.LeanSphincsStronglyUnforgeable` in [`Statement/LeanSphincs.lean`](../Statement/LeanSphincs.lean).) The hash `H` of `Th(P, A, M) = Truncate_16(H(P ‖ A ‖ M))` is Keccak-256, the sponge over a uniformly random permutation `π` of the Keccak state, and the adversary queries `π` and `π⁻¹` besides the signing oracle. `Q` counts every permutation call on every path of the game, key generation, the honest signer and the final verification included (a hash of `n` bytes costs `⌊n / 136⌋ + 1`). [Sphincs/Axioms.lean](Sphincs/Axioms.lean) and [FORS/Axioms.lean](FORS/Axioms.lean) pin the axioms to `propext`, `Classical.choice` and `Quot.sound` with `#guard_msgs`; there is no `sorry` and no `native_decide`, and every numeric certificate is checked by the kernel.

## The route

1. **The random-oracle theorem** (a step, not an end statement): `FORS.h26_layered`, 127 bits of classical SUF-CMA security in the random-oracle model for `q` hash calls, `q / 2^127`, for upstream's model `FORS.Scheme` at the configuration `.layered 26 3 8 24 10 1182000000` (three layers of 10 + 8 + 8 from the top, FORS of 24 trees of height 10). The library [`FORS`](FORS) is leanVM's `formal/lean_sphincs` at `542b0353`, ported from Lean v4.31.0 and VCVio `cbd4144` to this repository's pins (Lean v4.34.1, Mathlib v4.34.1, VCVio `afa6593f`): names, namespaces and statements unchanged, the proofs repaired for the toolchain (VCVio's measure-valued `evalDist`, the `Pr{…}[…]` notation, renamed lemmas, deprecations removed so that warnings are errors, file-level heartbeat raises removed), and one helper file of our earlier port, [`FORS/Base/Probability.lean`](FORS/Base/Probability.lean). Upstream's [README](https://github.com/leanEthereum/leanVM/tree/542b0353/formal/lean_sphincs) describes the proof.
2. **The random-permutation model**: `Sphincs.Model.modelScheme_stronglyUnforgeable` ([ModelRpm.lean](Sphincs/ModelRpm.lean)). The model's game is the generic SUF-CMA game of `common` (`experiment_eq`), and `Common.SufCma.rpm_bound` (the indifferentiability of the Keccak-256 sponge from a random oracle, `Q² / 2^509`) gives `Q / 2^127 + Q² / 2^509 ≤ (Q + 1) · 2^-127` for `Q ≤ 2^128`.
3. **The statement's scheme is the model's**: [Model.lean](Sphincs/Model.lean) and [ModelSigner.lean](Sphincs/ModelSigner.lean) prove that each of the model's algorithms, its hash queries answered by Keccak-256 over `π`, is the statement's (`simulateQ_verify`, `simulateQ_keygen`, `simulateQ_sign`), through the maps of the keys and signatures: the model numbers the layers from the top, the statement from the bottom as the crate does (`toLayer`); a layer's path has the model's length or the statement's, equal at each layer (`signatureEquiv`); every hash input is the same bytes (`fieldBytes_hashDomainFields`). The model's signer is written for every shape; at this configuration every index lands (`landed`), so its randomizer search stops after one digest call, and every tree is kept whole (`keptHeight_eq`). [Transport.lean](Sphincs/Transport.lean) proves that such a scheme has the model's game, adversary by adversary, and [Bridge.lean](Sphincs/Bridge.lean) moves the bound across (`stronglyUnforgeable_of_model`).

## The model and the Rust code

`Statement/LeanSphincs.lean` transcribes the crate (citations at `542b0353`) and was checked against it by reading both sides and against the EthLib verification vectors of `542b0353` (`crates/signatures/tests/signatures/ethlib/sphincs/verify`: the 3 valid signatures accepted, the 17 tampered or mismatched ones rejected); it is not a mechanized refinement of the Rust. Its signer computes the crate's signature as the proofs' signer does, so that the budget counts the Lean signer's calls: the layers from the top down, each tree and FORS tree rebuilt where the crate reuses it, and the digest's first call once more before the digest. The secret key the game hands the signer is the scheme seed and the parameter, as key generation derived them; the crate's key is the seed `S0` alone and derives them again.
