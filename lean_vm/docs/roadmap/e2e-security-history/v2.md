# End-to-end knowledge soundness of leanVM aggregation — framework draft v2

(v1: `design-v1.md` in the same directory. Paper: `ePrint 2023/1646`, Chiesa–Guan–Samocha–Yogev
2023/1646; extracted text: the paper. Repo: `lean_vm`, branch mumbai.)

## Goal
One Lean theorem, Lean's three axioms, for the deployed aggregation (recursive, unbounded depth):
an adversary making ≤ Q oracle queries that gets the root accepted "knows" a valid leanXMSS /
leanSPHINCS signature for every signature claim and an opening for every DA claim, at every node of
the tree, except with probability ε(Q) independent of depth and tree size. Exactly one heuristic,
outside Lean, stated precisely.

## What round 1 established (four adversarial reviews)
- FATAL in v1: a parent re-checking its children's oracle tables in-circuit (the paper's literal
  weak PCD, §2.3 / Construction 6.8) makes node size grow with the subtree; with leanVM's 2^28 cap
  the idealized system rejects all large trees, so the theorem is vacuous where it matters. Tables
  must be checked once, outside every circuit.
- The paper's Theorem 1 is not needed as a separate layer: `final_ineq` (Rom/Final.lean:453) holds for
  every statement/proof accepted by `verify (look ℓ)` on the final log, and the engine
  `prEvent_romExperiment_le_of_logFreshStepBelow` takes any predicate on the cache. So a UNIVERSAL
  corollary of `romSound` is cheap: Pr[accept ∧ ∃ (x, π), `Rom.verify (cache) x π = some true` ∧ x,π
  doomed] ≤ (QA+QV)(εmax + failBound). Every per-node bad event (knowledge, batching, collisions,
  cycles) must likewise be ONE event over the cache, charged per query, never per node; otherwise a
  union bound over nodes reintroduces N.
- The compliance predicate's own hashing must be evaluated from the cache (split verification), and
  the deferral must ride in the PCD message.
- Termination of the extracted tree ("held by child i" chains) is not automatic: needs fuel and a
  no-cycle event.
- Signature validity should be relative to the oracle: then the result composes with leanXMSS /
  leanSPHINCS's own ROM unforgeability (same oracle; the extractor makes no queries) and yields
  NO-FORGERY. Validity under concrete BLAKE2s with an unbounded extractor is nearly vacuous.
- Baked concrete-BLAKE2s constants (AGG_SEED, `Guest/B1/Main/Consts.lean:44`; DA padding digests,
  `Guest/B1/Da/Pad.lean:65`, `Da/Link.lean:56-66`) do not equal oracle values; must be parameters.

## The framework (v2): deployed guest and proof format, oracle-blind Flock, tables checked at the top
Idealized system I(H), H : Bytes → Digest the byte-level random oracle (the existing ROM framework is
kept):
1. Node proofs: the DEPLOYED proof format of the DEPLOYED guest bytecode. No new guest, no new
   protocol data.
2. Flock-blind verification: the verifier `V°` is leanVM's verifier with the Flock matrix value taken
   as claimed and never checked (the bytecode claim is still checked/deferred as today). At inner
   nodes this is already what `verifyDeferred` does; at the root, `OuterChecks°` drops the matrix
   part of `DeferredClaim.Holds`.
3. Oracle consistency at the top: the idealized acceptance additionally requires every node's
   committed BLAKE2S table (the extracted execution's compression rows) to be consistent with the
   oracle as answered by the final cache (split verification, no queries):
   - the table is functional (equal inputs, equal outputs; duplicate rows allowed);
   - chain rules: distinct rows never share (output, counter); a first block starts at the
     IV⊕parameter block with t = 64; non-final rows advance t by 64; final row has f0 set, f1 = 0,
     t ≤ 64k, the message zero-filled past t;
   - every complete chain from the IV to a final row computes H(message) with H answered by the
     cache; intermediate chaining values are otherwise free.
   (Alternative granularity, kept open: f := the compression function as the oracle, every row a
   per-row check, native H := BLAKE2s mode over f; simpler table check, but re-bases the ROM
   framework for multi-block Merkle leaves and the seed, and relies on an ideal-compression
   heuristic, weaker given known distinguishers on BLAKE2s's compression function with improper
   initialization (Guo et al. 2013/467).)
4. The heuristic (single, outside Lean): attacks on the deployed aggregation are no more effective
   than attacks on I(H) at the same number of hash queries: i.e. "rows that Flock proves are concrete
   BLAKE2s compressions (matrix claim checked at the root)" ≈ "rows consistent with a random oracle,
   checked natively", plus "BLAKE2s ≈ random oracle". Same circuit, same proof format: exactly the
   paper's "calls to the hash in the proved computation are lifted" (§2.3), with the checks moved out
   of the circuit instead of into the parent.

## Lean components
- C1 Spec, relativized: `NodeRel^H` (signatures via the HasQuery-generic schemes at H, DA at H with
  padding digests as parameters, `statementDigest^H`, `batch^H` with the batching start digest a
  parameter, `verifyDeferredWith H`), `OuterChecks°`, `TablesConsistent`, the e2e statement.
- C2 ISA/semantics parametric in the BLAKE2S row semantics: `ValidExecution^g` with
  `CompressCells^g` for a function g (concrete g = compress gives today's definitions back by `rfl`);
  the guest proofs (B1/B2) generalized over g (B2 already treats BLAKE2S symbolically; B1 funnels
  through a few hash lemmas: `compressCells_iff`, `blake2s_default`, the FS iffs).
- C3 Flock-blind knowledge soundness: leanVM KS for `V°` concluding `ValidExecution^g` with g the
  committed table's semantics (a relation until `TablesConsistent` makes it a function). New protocol
  theorem; most sub-certificates reused, Flock's binding of rows to `compress` dropped.
- C4 Universal corollaries (via `final_ineq`) for `V°` and for `batch_rom`; collisions/cycles of H
  in the cache as global events.
- C5 Chain lemma: `TablesConsistent` ⇒ for every message the guest hashes,
  `blake2sBytes^g(x) = H(x)` (cache).
- C6 Extraction: path-indexed, fuel = |cache|+1; termination via a no-cycle event (cycle A→…→A in
  "held by child" requires a decoded memory to contain a digest output after the word was committed:
  a decoding-prediction event, bounded by q·q·L·cells/2^256 with L the Johnson list size) — riskiest
  piece.
- C7 E2E theorem and non-vacuity: an idealized honest prover exists (Flock with a free matrix value
  is satisfiable for any rows; tables built from H); a small concrete inhabitant/test.

Bound: κ_{V°}(QA + QV) + Q·2/|E| (batching) + O(Q²)/2^256 (collisions, cycles, decoding prediction),
QV ≈ 13213 (root verification only), independent of depth and size.

## Open questions for round 2
1. Is the Flock-blind, top-checked idealization a correct relativized system (soundness of C3+C5:
   can a prover exploit free matrix value + free intermediates)? Does V° keep every other binding
   (slices bound by the stacked opening; ring switching)?
2. Is "deployed ≈ I(H)" a single heuristic of the paper's kind, and is I(H) non-vacuous?
3. Byte-level with chain rules vs ideal compression: which is better, all things considered?
4. C2 cost: is parametrizing `ValidExecution` by g feasible (it rebuilds everything; ~265k guest lines
   depend on it), mechanically (section variable / typeclass) or not?
5. C6 termination: is there a simpler correct argument, or a statement form that avoids it?
6. Anything missing for the final theorem to mean "no forgery" after composing with lean_xmss /
   lean_sphincs ROM unforgeability (oracle types `Digest` vs `BitVec 256`, adversary randomness,
   programming)?
