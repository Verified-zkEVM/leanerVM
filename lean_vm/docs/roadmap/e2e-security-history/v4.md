# End-to-end security of leanVM aggregation — framework draft v4

(History v1–v3 alongside; paper `ePrint 2023/1646`, text the paper; repo
`lean_vm`; guest `.leanvm/crates/rec_aggregation/guests/lean_ethereum.py`.)

## 0. The claim, in one sentence
In the random-oracle model with honest signers, no adversary making ≤ Q hash queries (its own,
the honest signers' and the verifiers', all counted) gets the idealized aggregation verifier V_I to
accept a root statement containing a leanXMSS/leanSPHINCS claim (pk_j, m) that honest signer j never
signed, or a root DA claim not backed by a codeword, except with probability ε(Q) — independent of
the aggregation tree's depth and size for fixed Q. Heuristic (single, outside Lean): the deployed
aggregation is as hard to forge against as V_I at the same Q.

## 1. Decisions (settled by rounds 1–3, ten reviews)
D1 Byte-level random oracle H : Bytes → Digest (the existing ROM framework and all three scheme
   proofs use it). Not an ideal compression function.
D2 Deployed guest bytecode and deployed proof format, unchanged. No new guest, no protocol variant,
   no in-circuit re-checks.
D3 V° := `verifyExecution` with the bytecode value `.computed` and the Flock lincheck terminal
   `require` (Verifier.lean:1990) deleted — one program per statement. Lemmas: deferred acceptance
   with a true bytecode claim ⇒ V°; deployed `.computed` acceptance ⇒ V°. Root `OuterChecks°` =
   DA vector digests ∧ bytecode part of `DeferredClaim.Holds`.
D4 Table rule (standard chains, active rows = executed BLAKE2S instructions of the decoded image;
   padding rows excluded; nine cells canonical, as the bus enforces): rows r₁…r_k form a standard
   chain of x (ℓ = |x|, k = max(1,⌈ℓ/64⌉)) iff r₁.cv = paramIv, r_{i+1}.cv = r_i.out, for i<k block i
   with t = 64i, f0 = f1 = 0, r_k the zero-filled last block with t = ℓ, f0 = 0xFFFFFFFF, f1 = 0.
   TableOK^H(rows): for every x and standard chain of x, out(r_k) = H(x). Rows on no chain free.
D5 Constants as parameters: batching start s0 (deployed: AGG_SEED = BLAKE2s(label)), DA padding
   (pc, pr) via `commitCodewordsWith H pc pr` in lean_da (deployed by `rfl` to the H-derived ones);
   `NodeRel`'s seed `fiatShamirIvWith H`; `paddingInstance` stays concrete (bus-pinned, inactive).
D6 Every bad event is one event over the (visible) log, charged per query; never a per-node union.
D7 Claims are those of the ROOT statement (inner DA claims carry no pinned vector digest), followed
   down `Holder.child` to a direct witness; "every node" is only the induction invariant.

## 2. The idealized verifier V_I (an algorithm; non-succinct; not flattening)
Idealized proof Π = (s, π, M), M a finite map from commitment roots to level-0 words. For a node
ν = (x = (guest, PI), π): its root r(π) and sizes are read off π's stream; Cand(W) = Johnson-list
candidates at `thrOf`; M3Holds° = the leanISA constraints with the Flock-blind BLAKE2S guard.
V_I^H(s, Π):
1. PI₀ := statementDigest^H(seed^H, s); require V°^H(guest, PI₀, π) and OuterChecks°^H(s).
2. N := least set containing (guest, PI₀, π), closed under: for ν ∈ N, q ∈ Cand(M(r(π))) with
   M3Holds°(x, q), every child (s_c, f_c, π_c) of decode(image q) gives
   (guest, statementDigest^H(seed^H, s_c), π_c) ∈ N. (Finite: ≤ |M|·L·children.)
3. For every ν ∈ N: M(r(π)) is defined and well shaped, MerkleRoot^H(M(r(π))) = r(π), and for every
   q ∈ Cand(M(r(π))) with M3Holds°(x, q): TableOK^H(activeRows q).
V_I never asserts that a candidate exists and never verifies a child's proof natively; bogus
children are caught only through knowledge soundness — exactly recursion's contribution.
Completeness: honest words are exact codewords and Cand is the honest stack (A ≥ √ρ·n > ρn).
Noisy words are admitted (proximity soundness stays inside the theorem).

## 3. The honest-signer game and the visible log (the O-SNARK issue)
The adversary gets coins (unifSpec), the hash oracle, and signing oracles for n_x leanXMSS and n_s
leanSPHINCS honest keys (limits enforced: no leaf reuse; `signatureLimit`); every returned signature
is re-verified with visible queries. The VISIBLE log = adversary's queries + re-verification
queries + V_I's queries; the signers' own queries are hidden but counted in Q. Extraction and the
cache-form consistency read only the visible log (reading the full cache lets extraction descend
into signer secrets, e.g. y = H(P‖A_prf‖S) revealed by a signature, then S).
New bad event LateReveal: a visible input references (chunk 0/32, `RootOf`) the full output of a
hidden entry that becomes visible later; bounded per scheme by (i) re-verification exposing
verification paths, (ii) the signer revealing ≤ 128 bits of any other hidden output, (iii) S-derived
inputs unreachable: ≈ Q·3/2^128 (to be checked per scheme).

## 4. The Lean theorem chain
T1 (universal KS, cache/visible-log form). For V° (and for the bytecode-only batching program): one
   event "some (x, π) accepted by the run answered from the visible log is doomed" ≤ (Q+QV)(εmax +
   failBound) (from `final_ineq`, Rom/Final.lean:453, and the engine's cache predicates), extended to
   the honest-signer game (LateReveal; coins forwarded).
T2 (guest, cache form). For any table consistent with the visible log: a valid V°-execution of the
   guest decodes to `NodeRelWith look_vis` (signatures/DA via `…With` over Option lookups, answered
   and true), children accepted by `verifyDeferredWith look_vis`. Needs B1 over a `HashModel`
   typeclass and an Option run layer.
T3 (termination). rank(ν) = log index of ν's statement-bytes entry; child edge: `RootOf` + ¬Fail
   (child PI absorbed as two halves into the parent's batching), `lt_of_chunk` along the batching
   chain, and ¬Pred96 (bytecodePoint[0]'s 24 bytes at offset 96 of the parent's statement input):
   rank strictly decreases; new term ≤ (Q+1)²/2^193. Fuel = |log|+1.
T4 (aggregate knowledge). Pr[V_I accepts ∧ ¬(every root claim followed down `.child` reaches a direct
   witness valid under the visible log)] ≤ κ_V°(Q) + κ_batch(Q) + failBound + (Q+1)²/2^193 +
   LateReveal + bridge, where the bridge (V_I's own queries never fresh: each node's Merkle root
   checked before descending) ≤ 2^27(Q+2^27)/2^256 + 2^-256 — never charged εmax.
T5 (no forgery). For each honest key, a black-box reduction to `leanXmss_security` /
   `leanSphincs_security` (Digest ≃ BitVec 256 RO transport; independent-RO commutation; hybrid over
   keys: factor n_x + n_s, stated), and a DA leg with its own ROM proof (lean_da's theorems take H as a
   fixed function and cannot be composed; needs `checker_sound`, the unproved NTT lemma
   `membershipVector = dual`, a DA `BadEntry` clause). Bound: T4 + (n_x+n_s)(Q+c)/2^127 + ε_DA.
T6 (completeness / non-vacuity of V_I): an honest I(H) prover (rows from H with injective fresh
   intermediates; Flock rounds any sumcheck-consistent values; per child `matrixValue` closing the
   in-circuit terminal, the matrix batching closed by hints; root matrix claim dropped) is accepted
   with probability ≥ 1 − ε_c.
T7 (sanity): every valid deployed execution tree with its words is accepted by V_I^{BLAKE2s}
   (not used in security).

## 5. The heuristic (outside Lean)
For every adversary against the deployed aggregation (`verifyAggregate`) with honest signers making
≤ Q BLAKE2s evaluations (in-circuit included), the forgery probability is ≤ the T5 bound. Its scope,
stated: (a) BLAKE2s ≈ RO natively; (b) Fiat–Shamir for in-circuit-verified proofs; (c) Flock's
R1CS + batched matrix claims ≈ oracle-consistent rows; (d) in-circuit chains ≈ visible queries.
Written argument why Khovratovich–Rothblum–Soukhanov-type attacks (FS hash computed inside the
proved statement) do not apply: the first challenge depends on the trace commitment (a fixed point
needed), the program is fixed and its bytecode claim batched to the root. Paper's caveats cited.
Unconditionally proved without the heuristic: the root level (`aggregate_sound_outer`).

## 7. Open questions for round 4
Q1 Is V_I (§2) right in its interaction with the visible log (§3): V_I's own Merkle/TableOK queries,
   the bridge lemma, and extraction from the visible log only?
Q2 Is LateReveal (§3) the complete list of new events for the honest-signer game? Is anything in T1's
   extension (coins, signing oracles, hidden queries) unsound with the potential method?
Q3 Is T6 needed in full, or does a weaker non-vacuity statement suffice for the heuristic to be
   meaningful? What is the minimal honest prover?
Q4 Is the theorem chain T1–T5 complete and correctly ordered; any gap between T4's conclusion and
   T5's reductions (validity "answered and true" under the visible log vs the schemes' winning
   condition)?
Q5 Final check: does anything make the final claim (§0) false, vacuous, or weaker than stated?
